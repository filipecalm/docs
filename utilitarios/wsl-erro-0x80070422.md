# WSL — erro `Wsl/0x80070422`

Runbook para o erro ao iniciar o WSL:

> O serviço não pode ser iniciado porque está desativado ou não tem dispositivos ativados associados.  
> Código: **Wsl/0x80070422**

Referência: [microsoft/WSL#11273](https://github.com/microsoft/WSL/issues/11273).

## Causa mais comum

O serviço **`WslService`** está desativado (`Disabled`) ou bloqueado por antivírus/firewall (ex.: AVG). No Windows 11 o serviço relevante é `WslService`; em versões antigas aparece `LxssManager`.

## Correção que resolveu (ordem recomendada)

Rodar no **PowerShell como Administrador**.

### 1. Antivírus / firewall

Se houver antivírus de terceiros (AVG, Avast, etc.):

1. Configure `WslService` como **Manual** (passo 2 abaixo).
2. Adicione à lista de apps permitidos:

   `C:\Arquivos de Programas\WSL\wslservice.exe`

   (em inglês: `C:\Program Files\WSL\wslservice.exe`)
3. Reinicie o Windows.
4. Confirme que o serviço continua como **Manual** (alguns AVs revertem a config).

### 2. Serviço em Manual (`demand`)

```powershell
sc.exe config wslservice start= demand
```

Depois teste:

```powershell
wsl -l -v
```

`start= demand` = tipo de inicialização **Manual** (o espaço depois de `=` é obrigatório no `sc.exe`).

### 3. Se o passo 2 não bastar — reinstalar distro via web

```powershell
wsl --install -d Debian --web-download
```

Troque `Debian` pela distro desejada (`Ubuntu`, etc.).

## Script do repositório — cuidado

[`scripts/ensure-wsl-services.ps1`](../scripts/ensure-wsl-services.ps1) (`npm run wsl:services`) força startup **Automatic** e tenta iniciar o serviço.

- Use quando o serviço está parado e **não** há AV interferindo.
- Se o problema for AVG/firewall (caso deste runbook), prefira **Manual** (`demand`) + allowlist — Automatic pode falhar de novo ou ser revertido pelo antivírus.

## `apt` só dentro do Linux

`sudo apt update` / `sudo apt upgrade` **não** rodam no PowerShell. Abra a distro:

```powershell
wsl
```

Dentro do shell Linux:

```bash
sudo apt update
sudo apt upgrade
```

## Escalação (se os passos acima falharem)

PowerShell **Admin**.

### A. Iniciar o serviço antigo (se existir)

```powershell
sc start LxssManager
```

### B. Habilitar features WSL / VM

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
```

Hyper-V completo só se precisar dele explicitamente:

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Hyper-V-All /all /norestart
```

Reinicie o PC.

### C. Virtualização no BIOS/UEFI

Ative **Intel VT-x** ou **AMD-V** (e, se existir, SVM / Virtualization Technology).

### D. Reparar imagem do Windows

```powershell
dism.exe /online /cleanup-image /restorehealth
wsl --install
```

### E. Windows Update

Configurações → Windows Update → verificar e instalar pendências.

### F. Unregister + reinstalar (destrutivo — apaga a distro)

```powershell
wsl --unregister Ubuntu
wsl --install
```

Substitua `Ubuntu` pelo nome em `wsl -l -v`. **Apaga o filesystem da distro.**
